Chapter 01

IaaS, PaaS, and SaaS — Understanding Cloud Models

Before writing a single line of code on AWS, you need to understand what cloud computing actually is and the three ways companies sell it to you.

What is Cloud Computing?

Cloud computing means renting computing resources over the internet instead of owning physical hardware. Instead of buying a server and putting it in a room, you rent one from AWS and pay only while you use it.

💡
Real-World Analogy Think about electricity. You don't build your own power plant to charge your phone — you just plug into the grid and pay per unit. Cloud computing is the same idea: plug into AWS's massive infrastructure, use what you need, pay for what you consume.

The key benefits are: no upfront cost (you don't buy hardware), scale on demand (add more capacity in seconds), and pay-as-you-go pricing.

The Three Cloud Service Models

IaaS

Infrastructure as a Service

AWS gives you the raw virtual hardware — a computer, storage, and a network connection. You install the OS, the software, and manage everything yourself.

🔧 AWS Examples: EC2, S3, VPC

👤 Used by: DevOps engineers, system admins

PaaS

Platform as a Service

AWS manages the OS and runtime for you. You just upload your code and it runs. You don't worry about patching servers or installing Python.

🔧 AWS Examples: Elastic Beanstalk, RDS

👤 Used by: Developers, small teams

SaaS

Software as a Service

A complete product delivered over the internet. You don't deploy anything — just sign up and use it. AWS builds the whole thing for you.

🔧 Examples: Gmail, Dropbox, Zoom

👤 Used by: Everyone — end users

Who Manages What? (The Shared Responsibility Model)

This table shows the crucial difference — as you move from IaaS → PaaS → SaaS, AWS takes on more responsibilities and you manage less:

LayerIaaS (EC2)PaaS (Beanstalk)SaaS
Your Application & DataYouYouAWS
Runtime (Python, Node)YouAWSAWS
Operating SystemYouAWSAWS
Physical ServersAWSAWSAWS
Network / DatacenterAWSAWSAWS
✅
Remember This IaaS = Most control, most work. SaaS = Least control, least work. In this course we work with IaaS (EC2) and PaaS (Elastic Beanstalk). By the end you'll understand why you'd choose one over the other.
Chapter 02

AWS Regions & Availability Zones

AWS doesn't run from one giant building. It's spread across the globe in carefully designed locations — and understanding this structure is essential for building reliable apps.

Regions

A Region is a specific geographic location where AWS operates data centers — like Mumbai, Virginia, or Ireland. Each region is completely independent. Data in Mumbai doesn't automatically go to Virginia.

Region CodeLocationNotes
us-east-1N. Virginia, USADefault for most tutorials; often cheapest
ap-south-1Mumbai, India 🇮🇳Best choice for Indian users — lowest latency
eu-west-1Ireland, EURequired for GDPR-compliant EU data
ap-southeast-1SingaporeGood for Southeast Asian users

Availability Zones (AZs)

Each Region is divided into Availability Zones. An AZ is one or more physical data centers, each with its own power supply, cooling, and internet connection. They are physically separated but connected by very fast, private fiber cables.

📍 Region: ap-south-1 (Mumbai)
ap-south-1a
🏢 Data Center 1 🏢 Data Center 2
ap-south-1b
🏢 Data Center 3
ap-south-1c
🏢 Data Center 4

Why Does This Matter?

  • Latency: Deploy in the region closest to your users. Mumbai for India, Virginia for US East Coast.
  • High Availability: Deploy your app across 2+ AZs. If one data center catches fire, the other AZs keep serving users. This is called fault tolerance.
  • Data Residency: Some laws (like GDPR in Europe) require user data to stay in a specific country. Regions enforce this.
  • Cost: The same EC2 instance type can cost slightly different amounts in different regions.
⚠️
Common Mistake Always check which region you're in on the AWS Console (top-right corner). Resources are region-specific — an EC2 instance you launch in Mumbai won't show up if you switch to the Virginia region view.
Chapter 03

Launching EC2, SSH Access & Security Groups

EC2 (Elastic Compute Cloud) is the heart of AWS. It's a virtual machine you rent by the hour. Let's launch one and connect to it.

What is an EC2 Instance?

An EC2 instance is simply a virtual computer running in AWS's data center. It has a CPU, RAM, storage, and a network connection. You choose the specifications and you're billed per hour (or per second for Linux).

Instance Types — Naming Convention

EC2 types follow a pattern: family + generation + size. For example, t2.micro means:

  • t = "burstable" family (general purpose, cheap)
  • 2 = 2nd generation
  • micro = smallest size (1 vCPU, 1 GB RAM)

For this course, always use t2.micro — it's free-tier eligible (750 hours/month free for new accounts).

Step-by-Step: Launch Your First EC2

1

Open EC2 Dashboard: AWS Console → Services → EC2 → Click "Launch Instance"

2

Name it: Give your instance a name like my-web-server

3

Choose an AMI (Amazon Machine Image): This is your operating system. Choose Ubuntu Server 22.04 LTS. An AMI is like a snapshot of an OS — a ready-to-boot system image.

4

Choose Instance Type: Select t2.micro (look for the "Free tier eligible" label)

5

Create a Key Pair: This is your SSH password, but in the form of a file. Click "Create new key pair", name it my-key, choose RSA + .pem format, and download it. Save this file safely — you cannot download it again.

6

Configure Security Group: Under "Network Settings", allow SSH (port 22). We'll add more ports later.

7

Launch: Click "Launch Instance". After ~60 seconds it will be running. Copy the Public IPv4 address from the instance details.

Security Groups — Your Cloud Firewall

A Security Group is a set of firewall rules that controls which network traffic is allowed into (and out of) your EC2 instance. Think of it as a bouncer at the door — only traffic that matches a rule gets in.

🔒
Security Rule #1 — Never Expose SSH to the World Setting SSH (port 22) source to 0.0.0.0/0 means anyone on earth can try to log in. Always restrict SSH to My IP (AWS fills your IP automatically) or a specific IP range.

Common Ports to Know

SSH — Connecting via Terminal

SSH (Secure Shell) lets you open a terminal inside your EC2 instance from your laptop, as if you were physically sitting in front of that server.

Mac / Linux — Fix key permissions first

Terminal
# The key file must not be readable by other users on your machine
chmod 400 ~/Downloads/my-key.pem

Connect to your instance

Terminal
# Command format:
# ssh -i <your-key-file> <username>@<public-ip>

# For Ubuntu AMI (most common):
ssh -i ~/Downloads/my-key.pem ubuntu@3.109.45.210

# For Amazon Linux 2023:
ssh -i ~/Downloads/my-key.pem ec2-user@3.109.45.210
🪟
Windows Users Use Windows Subsystem for Linux (WSL) — open it from the Start menu and the commands above work exactly the same. Alternatively, use Git Bash or MobaXterm. Modern Windows 11 also supports the ssh command directly in PowerShell.

First thing to do after logging in

EC2 Terminal (Ubuntu)
# Update the package list and upgrade installed software
sudo apt update && sudo apt upgrade -y

# Check Python — Ubuntu 22.04 comes with Python 3.10+
python3 --version

# Install pip (Python package manager)
sudo apt install python3-pip python3-venv -y

# Exit the SSH session when done
exit
Chapter 04

Deploying a Python App on EC2

Now that you can SSH into an EC2 instance, let's put a real Python web API on it and make it accessible from the internet.

What We're Building

A FastAPI application — a modern Python web framework that's fast, easy to use, and automatically generates API documentation. We'll deploy it on EC2 and access it from a browser.

Step 1 — Set Up the Environment on EC2

EC2 Terminal
# Create project directory
mkdir ~/myapp
cd ~/myapp

# Create a virtual environment
# (keeps your project's packages separate from the system)
python3 -m venv venv

# Activate the virtual environment
source venv/bin/activate
# Your prompt changes to: (venv) ubuntu@ip...

# Install FastAPI and Uvicorn (the web server)
pip install fastapi uvicorn

Step 2 — Write the App

main.py
from fastapi import FastAPI

app = FastAPI()

# The "/" route — what you see when you visit http://your-ip:8000/
@app.get("/")
def home():
    return {"message": "Hello from AWS EC2! 🚀"}

# A route with a path parameter
@app.get("/greet/{name}")
def greet(name: str):
    return {"message": ff"Hello, {name}!"}

# Health check endpoint — used by load balancers
@app.get("/health")
def health():
    return {"status": "ok"}

Create this file on EC2 using the nano editor: type nano main.py, paste the code, then press Ctrl+X → Y → Enter to save.

Step 3 — Run the App

EC2 Terminal
# --host 0.0.0.0 means "accept connections from any IP"
# Without this, only localhost (the server itself) can connect
# --reload auto-restarts when code changes (for development)
uvicorn main:app --host 0.0.0.0 --port 8000 --reload
🌐
Test it in your browser Go to http://<YOUR-EC2-PUBLIC-IP>:8000 — you should see the JSON response. Also try /docs — FastAPI auto-generates an interactive API documentation page!

Make sure port 8000 is open in the Security Group (add an inbound rule: Custom TCP, Port 8000, Source 0.0.0.0/0).

Step 4 — Keep it Running After You Disconnect

When you close the SSH session, your process stops. Use nohup to keep it alive:

EC2 Terminal
# nohup = "no hang up" — keeps process running after logout
# & = runs in background
nohup uvicorn main:app --host 0.0.0.0 --port 8000 &

# Check it's running
ps aux | grep uvicorn

# Stop it later
pkill -f uvicorn

Bonus — Copy Files from Your Laptop to EC2 (SCP)

You don't have to write code directly on EC2. Write it on your laptop and use scp (Secure Copy) to transfer it:

Your Laptop Terminal
# Copy one file
scp -i my-key.pem main.py ubuntu@3.109.45.210:~/myapp/

# Copy an entire folder (-r for recursive)
scp -i my-key.pem -r ./myapp/ ubuntu@3.109.45.210:~/
Chapter 05

Deploying FastAPI to Elastic Beanstalk

Managing EC2 manually is fine for learning, but in production you want auto-scaling, health monitoring, and easy deployments. That's what Elastic Beanstalk gives you.

What is Elastic Beanstalk?

Elastic Beanstalk (EB) is AWS's Platform as a Service. You give it your code (as a ZIP file or via CLI), and it automatically:

  • Launches EC2 instances
  • Sets up a Load Balancer to distribute traffic
  • Configures Auto Scaling (adds more servers when traffic spikes)
  • Monitors health and restarts crashed servers

You just focus on writing your app.

How Elastic Beanstalk Works
Your Code
.zip upload
→
Elastic
Beanstalk
→
EC2 Instances
Load Balancer
Auto Scaling Group

You manage your code. AWS manages the infrastructure.

Required Project Structure

Elastic Beanstalk expects a specific file name for Python: the main file must be called application.py and the WSGI object inside it must also be called application.

Project Structure
my-fastapi-app/
├── application.py       ← MUST be named this for Elastic Beanstalk
├── requirements.txt     ← list of all pip packages
└── .ebextensions/
    └── python.config    ← tells EB how to start your app

application.py

application.py
from fastapi import FastAPI

# ⚠️ The variable MUST be named 'application' — not 'app'
# Elastic Beanstalk specifically looks for this name
application = FastAPI()

@application.get("/")
def root():
    return {"message": "FastAPI running on Elastic Beanstalk!"}

@application.get("/health")
def health():
    return {"status": "ok"}

requirements.txt

requirements.txt
fastapi
uvicorn[standard]

.ebextensions/python.config

.ebextensions/python.config
option_settings:
  aws:elasticbeanstalk:container:python:
    WSGIPath: application:application

Deploy with the EB CLI

Terminal (your laptop)
# 1. Install the EB CLI
pip install awsebcli

# 2. Go to your project folder
cd my-fastapi-app

# 3. Initialize — follow the prompts:
#    - Select region (ap-south-1 for Mumbai)
#    - Create a new application
#    - Select Python as the platform
eb init

# 4. Create an environment and deploy
eb create fastapi-prod-env

# 5. Open your deployed app in the browser
eb open

# 6. When you make code changes, just run:
eb deploy

# 7. Check logs if something breaks
eb logs

# ⚠️ IMPORTANT: When done, terminate to stop charges
eb terminate fastapi-prod-env
💰
Cost Warning — Always Terminate When Done Elastic Beanstalk creates real EC2 instances and Load Balancers. These cost money per hour even when idle. Always run eb terminate <env-name> after practice sessions. Check AWS Billing dashboard regularly.

Chapter 06

Serverless — AWS Lambda & API Gateway

Serverless is the next evolution. No servers to manage, no idle costs, infinite automatic scaling. Here's how it works and how to build with it.

What is "Serverless"?

The name is misleading — there are servers, but you never see, manage, or pay for them when idle. You write a function, upload it, and AWS runs it whenever needed. You pay only for the exact milliseconds it runs.

Traditional Server (EC2)Serverless (Lambda)
Running24/7, even with 0 trafficOnly when triggered
BillingPer hour of uptimePer millisecond of execution
ScalingManual or configured Auto ScalingAutomatic — 0 to 1 million instantly
MaintenanceYou patch OS, update softwareNone — AWS handles everything
💡
Real World Example Imagine you're building a "resize uploaded image" feature. With EC2: a server runs 24/7 waiting for uploads. With Lambda: a function fires only when an image is uploaded, resizes it in 200ms, and you pay for those 200ms. If nobody uploads all night, you pay $0.

AWS Lambda — Core Concepts

  • A Lambda Function = a single function AWS runs on your behalf
  • Supports Python, Node.js, Java, Go, Ruby
  • Max runtime: 15 minutes per call
  • Free tier: 1 million free requests/month (stays free forever)
  • Triggered by events: HTTP requests, file uploads, scheduled timers, database changes, etc.

Your First Lambda Function — The Handler

Every Lambda function needs a handler — the entry point that AWS calls. It receives two parameters: event (the incoming data) and context (runtime metadata).

lambda_function.py
import json

def lambda_handler(event, context):
    """
    event   → the incoming data (from API Gateway, S3, etc.)
    context → runtime info (function name, remaining time, etc.)
    """

    # Get a query parameter called 'name' if provided
    params = event.get('queryStringParameters') or {}
    name = params.get('name', 'World')

    # Return value must follow this exact structure for API Gateway
    return {
        'statusCode': 200,
        'headers': {'Content-Type': 'application/json'},
        'body': json.dumps({
            'message': ff'Hello, {name}! Running on Lambda 🚀'
        })
    }

Create a Lambda Function (Console)

1

AWS Console → Lambda → Create Function

2

Choose "Author from scratch" → Name it my-hello-lambda → Runtime: Python 3.12 → Click Create

3

Paste your code in the inline editor → Click Deploy

4

Test it: Click Test → Create a new test event → Click Test → See the response in the "Execution result" panel

API Gateway — Give Your Lambda a URL

Lambda has no public URL by default. API Gateway is a fully managed service that creates an HTTPS endpoint that triggers your Lambda function when someone makes an HTTP request to it.

→

→

API Gateway handles SSL, rate limiting, and auth. Lambda handles your business logic.

Connect API Gateway to Lambda

1

AWS Console → API Gateway → Create API → Choose HTTP API (simpler, cheaper than REST API)

2

Add Integration: Select Lambda → choose your my-hello-lambda function

3

Configure route: Method = GET, Path = /hello

4

Deploy: Stage = $default → AWS generates your public URL like https://abc123.execute-api.ap-south-1.amazonaws.com/hello

5

Test it! Open the URL in your browser. Add ?name=YourName to see the name parameter in action.

Using External Libraries in Lambda

Lambda doesn't have most PyPI packages pre-installed (except boto3, the AWS SDK). To use packages like requests, you need to bundle them with your code in a ZIP file.

Terminal (your laptop)
# Create a folder for the deployment package
mkdir lambda_pkg && cd lambda_pkg

# Install libraries INTO this folder (not system-wide)
# -t . means "install here"
pip install requests -t .

# Copy your function code into the folder
cp ../lambda_function.py .

# Zip everything
zip -r deployment.zip .

# Upload via AWS CLI
aws lambda update-function-code \
  --function-name my-hello-lambda \
  --zip-file fileb://deployment.zip
